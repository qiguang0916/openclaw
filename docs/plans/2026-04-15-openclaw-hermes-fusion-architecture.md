## 1. 执行摘要

### 1.1 一句话定位

> **OpenClaw 负责今天的高效执行，Hermes 负责让整个团队明天更聪明。**

### 1.2 核心价值主张

本方案将两套成熟的 AI Agent 框架通过标准化 MCP 协议融合为一个**会自我进化的智能团队系统**：

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   普通 Agent 系统        VS       OpenClaw × Hermes 融合系统      │
│   ─────────────────              ──────────────────────────     │
│                                                                 │
│   静态 Prompt + 工具    →→→      动态学习 + 技能进化               │
│   单次任务即忘           →→→      经验累积 + 持续改进               │
│   重复犯同类错误         →→→      错误驱动技能创建                  │
│   Agent 各自孤立        →→→      团队协作 + 知识共享               │
│   需手动维护能力         →→→      自动进化 + 零人工干预             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 关键指标预期

| 指标                      | 当前基线     | 融合后预期 | 提升幅度 |

| 任务重复失败率            | ~30%         | <5%        | ↓ 83%    |
| 内容创作引用真实素材比例  | ~40%         | >90%       | ↑ 125%   |

## 2. 问题陈述与设计动机

### 2.1 现有架构的根本局限

当前 OpenClaw 系统是一个优秀的**生产编排框架**，但存在三个系统性缺陷：

#### 缺陷一：静态智能，无法自我进化

```
现状：
  用户指出错误 → Agent 纠正 → 会话结束 → 下次重蹈覆辙

根因：
  AGENTS.md + Prompt 是静态文件，Agent 没有机制将
  运行时经验转化为持久化的行为改变
```

#### 缺陷二：信息孤岛，团队无法共享智慧

```
现状：
  pub-chief 学到的内容规律 ≠ dy-chief 也能使用
  dev-lead 的代码经验 ≠ codex-builder 也知道

根因：
  各 Agent 记忆空间完全隔离（这是安全要求），
  但缺少"知识提炼→共享"的跨层机制
```

#### 缺陷三：研究能力薄弱，内容靠模型幻觉

```
现状：
  pub-write 在没有真实素材的情况下创作
  → 内容脱离实际 → 用户二次修改成本高

根因：
  OpenClaw 缺少深度研究工具（Tavily、Firecrawl、
  浏览器自动化等），Hermes 恰好有完整实现
```

### 2.2 为什么选择 Hermes 而非自研

| 方案                           | 开发周期                    | 质量风险           | 维护成本 | 推荐  |
| ------------------------------ | --------------------------- | ------------------ | -------- | ----- |
| 在 OpenClaw 中自研自我进化模块 | 3-6 个月                    | 高（未验证）       | 高       | ✗     |
| 直接替换为 Hermes              | 不可行（丢失102+ 渠道能力） | —                  | —        | ✗     |
| **MCP 桥接融合（本方案）**     | **1-2 周**                  | **低（现有代码）** | **低**   | **✓** |

**Hermes 提供的不可替代价值**：

- ✅ 已经过生产验证的 `skill_manager_tool`（原子写入 + 安全扫描 + 模糊匹配）
- ✅ `on_delegation` 学习钩子（委派完成即触发学习，非侵入式）
- ✅ agentskills.io 标准兼容（与 OpenClaw SKILL.md 格式一致）
- ✅ 多记忆提供商支持（Honcho、mem0、RetainDB 等）
- ✅ `hermes mcp serve` 已实现，10 个工具今天就能调用

### 2.3 技术可行性验证

MCP 桥接可行性已通过现有方案文档（`HERMES_OPENCLAW_MCP_PLAN.md`）确认：

```
传输层：stdio（两边均支持，无网络配置需求）
协议层：FastMCP + OpenClaw MCP Client（已有 mempalace 案例）
工具格式：JSON Schema（完全标准化）
```

### 4.2 架构设计决策说明

**为什么保持 OpenClaw 作为执行主体？**

OpenClaw 拥有 102+ 渠道集成、生产级路由、精细权限控制和成熟的 SubAgent 调度系统——这些是数月工程积累，不应替换。Hermes 的价值在于作为**智能进化后端**，而非替代前端。

**为什么使用 MCP 而非 HTTP API？**

```
MCP (stdio) 优势：
  ✓ 无端口冲突，无网络配置
  ✓ 进程级隔离，不影响主进程
  ✓ 双方均已原生支持（mempalace 已有完整案例）
  ✓ 标准化协议，工具发现自动化
  ✓ 工具调用失败不会崩溃主进程
```

**为什么 Hermes 每个域有独立 Twin，而非共享一个？**

```
独立 Twin 优势：
  ✓ 技能库专域化（内容技能不污染开发技能库）
  ✓ 记忆独立（内容团队的用户偏好 ≠ 开发团队的偏好）
  ✓ 并行进化（多个 Twin 同时工作，不互相阻塞）
  ✓ 故障隔离（单个 Twin 失败不影响其他团队）
```

## 11. 风险矩阵与应对策略

### 11.1 技术风险

| 风险                         | 概率 | 影响 | 应对策略                | 预防措施                    |
| ---------------------------- | ---- | ---- | ----------------------- | --------------------------- |
| Hermes MCP server 冷启动失败 | 中   | 高   | 健康检查 + 自动重启     | 保持长进程，禁止每次重启    |
| 技能同步冲突                 | 中   | 中   | 基于时间戳的冲突解决    | 命名前缀隔离（`content-*`） |
| Hermes 创建低质量技能        | 高   | 中   | 人工审批通道            | 安全扫描已内置              |
| MemPalace ↔ Hermes 记忆污染  | 低   | 高   | 单向同步 + 命名空间隔离 | 只桥接 L3 技能层            |
| SubAgent 深度超限            | 低   | 中   | 明确深度限制配置        | maxSpawnDepth=2             |
| Hermes Python 进程崩溃       | 中   | 中   | 进程监控 + 自动重启     | 与 OpenClaw 进程分离        |

### 11.2 运营风险

| 风险                                  | 概率 | 影响 | 应对策略                         |
| ------------------------------------- | ---- | ---- | -------------------------------- |
| 技能库膨胀（大量低价值技能）          | 高   | 低   | 定期自动清理（30天无使用即归档） |
| Agent 循环委派（死循环）              | 低   | 高   | 委派深度限制 + 超时保护          |
| 成本失控（Hermes 研究耗费大量 token） | 中   | 中   | 每任务成本上限 + 预算告警        |
| 用户隐私泄露（记忆桥接）              | 低   | 高   | 严格隔离 L2 私有记忆，审计日志   |

### 11.3 降级方案

```
  正常状态               降级状态
  ────────               ────────

  OpenClaw + Hermes     → OpenClaw 独立运行（Hermes 故障时）
  Hermes Twin 进化      → 手动更新 SKILL.md（进化暂停时）
  MCP 桥接双向          → 单向降级（只保留 OC → Hermes）
  自动技能同步           → 手动触发同步（cron 故障时）

  每个降级状态下，OpenClaw 均可独立完成任务（无功能中断）
  Hermes 是增强层，不是依赖层
```

## 12. 性能与成本模型

### 12.1 延迟模型

```
  普通任务（不触发 Hermes）：
  用户请求 → Gateway → Lead → Worker → 响应
  延迟：~5-15 秒（取决于 LLM 响应速度）

  带研究的任务（触发 Hermes）：
  用户请求 → Gateway → Lead → hermes:send → Hermes 研究
           → 结果回写 → Worker → 响应
  延迟：~30-90 秒（Hermes 研究阶段）
  建议：对用户展示"研究中..."进度状态

  进化触发（后台异步）：
  任务完成 → 后台触发 on_delegation → 技能更新
  延迟：异步，不影响主流程
  对用户：完全透明
```

### 12.2 Token 成本模型

| 场景                 | 涉及模型            | 预估 token | 成本估算 |
| -------------------- | ------------------- | ---------- | -------- |
| 普通文章创作         | deepseek + doubao   | ~10k       | ~$0.03   |
| 带 Hermes 研究的文章 | + claude-sonnet-4-6 | ~30k       | ~$0.15   |
| 进化触发（后台）     | claude-sonnet-4-6   | ~20k       | ~$0.10   |
| 元学习（每日一次）   | claude-sonnet-4-6   | ~50k       | ~$0.25   |

### 12.3 成本优化策略

```
  策略一：Hermes Twin 使用更便宜的模型（deepseek）做初筛
          只有复杂分析才升级到 claude-sonnet-4-6

  策略二：技能缓存——已有高质量技能时跳过 Hermes 研究
          命中率随时间提升（预期 6 个月后 >70% 命中）

  策略三：批量进化——积累 5 个相似失败后统一处理
          减少 Hermes 调用次数，提升每次调用价值

  策略四：元学习频率控制——hermes-meta 每日仅运行一次
          避免高频低价值的全局分析
```

### D. 技能同步脚本（skill-hub）

```bash
#!/bin/bash
# skill-sync.sh - 同步 Hermes 技能到 OpenClaw workspace

HERMES_SKILLS="/Users/qiguang/.hermes/skills"
OC_WORKSPACES="/Users/qiguang/.openclaw"

# 内容团队技能同步
rsync -av --checksum \
  "${HERMES_SKILLS}/content/" \
  "${OC_WORKSPACES}/workspace-pub-chief/skills/"

# 开发团队技能同步
rsync -av --checksum \
  "${HERMES_SKILLS}/dev/" \
  "${OC_WORKSPACES}/workspace-dev-lead/skills/"

# 共享技能同步（所有 workspace）
for workspace in ${OC_WORKSPACES}/workspace-*/; do
  rsync -av --checksum \
    "${HERMES_SKILLS}/shared/" \
    "${workspace}skills/shared/"
done

echo "[$(date)] Skill sync completed"
```

## 文档结语

本方案的核心理念是**让 AI Agent 团队具备像优秀工程师团队一样的学习能力**：

- 每次失败都变成改进的机会（而非下次重蹈覆辙）
- 团队的集体智慧通过技能库沉淀和共享
- 新成员（新 Agent）一加入就能站在整个团队的经验积累之上
- 系统越用越聪明，而不是静止在初始配置的水平

两套系统的融合不是简单的功能叠加，而是形成了**执行力（OpenClaw）× 进化力（Hermes）**的乘法效应。
