# 记忆工具使用行为协议 V1

> 适用对象：openclaw-optimizer（贾维斯）及其他配置了记忆工具的 agent  
> 创建日期：2026-04-14  
> 维护负责：openclaw-optimizer / jarvis-memory

---

## 1. 最重要的一条规则

**记忆工具是直接可用的工具（tool calls），不需要通过任何 CLI 命令来发现它们。**

绝对不要运行：

- `openclaw tools list`（该命令不存在）
- `openclaw memory list`（用于查看记忆状态，不是工具发现）
- 任何 `exec` 命令来确认工具是否存在

如果工具出现在你的工具列表里，它就是可用的。直接调用即可。

---

## 2. 可用工具速查表

### 核心记忆接口（推荐首选）

| 工具名            | 用途                                       |
| ----------------- | ------------------------------------------ |
| `memory_search`   | 语义检索：找过去的对话、决策、偏好         |
| `memory_get`      | 精确读取：通过 synthetic path 读取完整内容 |
| `memory_write`    | 写入记忆：保存重要事实/决策/偏好到 drawer  |
| `memory_update`   | 更新记忆：修改已有 drawer 或 KG 事实       |
| `memory_delete`   | 删除记忆：移除过期或错误的记忆             |
| `memory_kg_query` | KG 查询：结构化查询知识图谱                |
| `memory_stats`    | 查看记忆系统状态统计                       |

### MemPalace 原生工具（需要更细粒度控制时使用）

| 工具名                      | 用途                                      |
| --------------------------- | ----------------------------------------- |
| `mempalace_add_drawer`      | 直接写入 drawer（绕过 memory_write 封装） |
| `mempalace_kg_add`          | 直接写入知识图谱三元组                    |
| `mempalace_diary_write`     | 写入日记层（会话连续性反思）              |
| `mempalace_check_duplicate` | 写入前检查是否重复                        |
| `mempalace_search`          | 原始 drawer 搜索（不带 KG 聚合）          |
| `mempalace_kg_query`        | 原始 KG 查询                              |
| `mempalace_diary_read`      | 读取日记层                                |
| `mempalace_status`          | 查看 palace 原始状态                      |

## 3. 何时使用 memory_search

### 自动触发条件（遇到以下关键词主动 recall）

用户消息包含以下关键词时，在回复前先调用 `memory_search`：

- 中文：之前、上次、还记得、按以前、我喜欢、我说过、我们定过、历史、上回
- 英文：history、preference、remember、timeline、before、last time

### 不触发条件

- 普通问答、新话题、无需历史上下文的请求
- 不要在每条消息开头都 recall，节省 token

### 表达规范（重要）

调用记忆工具前后，**不要提及任何技术系统名称**（MemPalace、KG、drawer 等）。
使用自然的拟人表达：

| ❌ 不要这样说                   | ✅ 改为这样说                |
| ------------------------------- | ---------------------------- |
| 让我检查一下 MemPalace 中的记录 | 让我想想... / 稍等，回忆一下 |
| 搜索记忆库...                   | 嗯，印象里...                |
| 查询知识图谱                    | 我记得...                    |

**工具调用后必须继续输出文字回复**，无论搜索结果是否为空：

- 有结果：自然融入回复内容
- 无结果：说"暂时还不了解这方面，你可以告诉我～"之类的话，**不要沉默**

## 4. 何时写入记忆

以下内容值得用 `memory_write` 或 `mempalace_kg_add` 保存：

**写入 Drawer（`memory_write`）**：

- 重要对话结论、决策摘要
- 用户明确要求记住的信息
- 项目背景、约定、规范
- 需要未来搜索到的事实

**写入 KG（`mempalace_kg_add`）**：

- 持久化三元组事实，例如：
  - 用户 → 偏好 → 某语言/框架
  - 项目A → 截止日期 → 2026-06-01
  - 用户 → 角色 → 产品经理
- 有明确主语-谓语-宾语结构的长期事实

**写入 Diary（`mempalace_diary_write`）**：

- 会话反思、今日工作总结
- 下次对话的连续性提示
- 不适合用作事实来源

### 写入前的去重检查

写入 drawer 前，`memory_write` 会自动检查相似度（>=0.92 视为重复）。  
如果确认要覆盖，使用 `force: true` 参数。

---

## 5. 三层存储选择指南

```
需要保存什么？
├── 原文/证据/对话摘要/详细内容  →  Drawer（memory_write / mempalace_add_drawer）
├── 结构化事实/长期关系/用户属性  →  KG（mempalace_kg_add）
└── 会话反思/今日连续性笔记       →  Diary（mempalace_diary_write）
```

---

## 6. Synthetic Path 格式

`memory_search` 返回结果中包含 `path` 字段，格式为：

- Drawer：`mempalace/private/drawer/<wing>/<room>/<digest>`
- KG 事实：`mempalace/private/kg/<subject>/<predicate>/<object>`

用这些 path 调用 `memory_get` 精确读取完整内容，或 `memory_update` / `memory_delete`。

---

## 7. 作用域说明

- **私有（private）**：仅本 agent 可读写，默认
- **共享（shared）**：跨 agent 共享（仅配置了 readShared/writeShared 的 agent 可访问）

openclaw-optimizer 同时具有私有和共享读写权限。

---

## 8. 常见错误避免

| 错误行为                               | 正确做法                                   |
| -------------------------------------- | ------------------------------------------ |
| `exec: openclaw tools list` 来检查工具 | 直接调用工具，不需要检查                   |
| 每次回复前都 recall                    | 只在触发关键词时 recall                    |
| 把所有内容写入 KG                      | KG 只存三元组事实；详细内容用 drawer       |
| 不检查就反复写入相同内容               | memory_write 自动去重；必要时用 force=true |
| 用 path 字符串拼接代替搜索             | 先 memory_search，再用返回的 path          |
